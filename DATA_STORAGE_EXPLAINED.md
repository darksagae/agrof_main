# 📊 AGROF Data Storage Architecture

## 🎯 **How Your Data is Stored**

### **1. Firebase Authentication (User Identity)**
```javascript
Firebase Auth stores:
{
  uid: "firebase_abc123",           // Unique user ID (generated by Firebase)
  email: "user@agrof.com",          // User's email
  phoneNumber: "+256700000000",     // Phone number (optional)
  emailVerified: true,              // Verification status
  displayName: "John Doe"           // Full name
}
```

**Purpose**: Secure authentication, login/logout, email verification

---

### **2. Cloudinary (Profile Photos)**
```javascript
Photo Upload:
file:///path/to/photo.jpg 
    ↓ Upload via REST API
https://res.cloudinary.com/dsr8twjxe/image/upload/v123/agrof/profile_photos/firebase_abc123/profile.jpg

Stored at:
Cloudinary → agrof/profile_photos/{firebase_uid}/profile.jpg
```

**Purpose**: Cloud storage for images, automatic optimization, CDN delivery

---

### **3. Local Storage (User Profile Data)**
```javascript
AsyncStorage stores:
{
  "agrof_users": {
    "firebase_abc123": {              // Key = Firebase UID
      uid: "firebase_abc123",         // Same UID from Firebase Auth
      email: "user@agrof.com",        // From Firebase Auth
      fullName: "John Doe",           // From signup
      username: "johndoe",            // Customizable
      phone: "+256700000000",         // Editable (requires verification)
      profilePhoto: "https://res.cloudinary.com/.../profile.jpg",  // Cloudinary URL
      emailVerified: true,
      createdAt: "2025-10-10T...",
      updatedAt: "2025-10-10T...",
      firebaseAuth: true              // Flag indicating Firebase user
    }
  }
}
```

**Purpose**: Fast local access, offline capability, profile data storage

---

## 🔄 **Data Flow**

### **Sign Up:**
```
1. User enters: email, password, name, phone
   ↓
2. Firebase Auth creates account → generates UID
   ↓
3. User data saved to Local Storage (AsyncStorage) using Firebase UID as key
   ↓
4. Email verification sent by Firebase
```

### **Profile Photo Upload:**
```
1. User selects photo from device
   ↓
2. Photo uploaded to Cloudinary REST API
   ↓
3. Cloudinary returns URL: https://res.cloudinary.com/.../profile.jpg
   ↓
4. URL saved to Local Storage (AsyncStorage)
```

### **Profile Data Update:**
```
1. User edits username/phone
   ↓
2. Data saved to Local Storage (AsyncStorage)
   ↓
3. Firebase UID used as key to identify user
```

### **Sign In:**
```
1. Firebase Auth verifies credentials
   ↓
2. Firebase provides user UID
   ↓
3. App loads user data from Local Storage using UID
   ↓
4. Profile complete with photo URL from Cloudinary
```

---

## 📱 **What Happens Where**

| Data Type | Firebase Auth | Cloudinary | Local Storage |
|-----------|--------------|------------|---------------|
| **Email** | ✅ Primary | ❌ | ✅ Cache |
| **Password** | ✅ Encrypted | ❌ | ❌ |
| **Phone Number** | ✅ Stored | ❌ | ✅ Cache |
| **Email Verified** | ✅ Status | ❌ | ✅ Cache |
| **Firebase UID** | ✅ Generated | ❌ | ✅ As key |
| **Username** | ❌ | ❌ | ✅ Stored |
| **Full Name** | ✅ displayName | ❌ | ✅ Cache |
| **Profile Photo** | ❌ | ✅ Image file | ✅ URL only |
| **Created Date** | ✅ Timestamp | ❌ | ✅ Stored |

---

## 🔐 **Security & Sync**

### **Firebase UID = Universal Key**
```
Firebase creates:     uid = "firebase_abc123"
                           ↓
Cloudinary stores:    agrof/profile_photos/firebase_abc123/
                           ↓
Local Storage key:    agrof_users["firebase_abc123"]
```

**Everything is connected by the Firebase UID!**

### **Why This Architecture?**

✅ **Firebase Auth**: Industry-standard authentication, secure
✅ **Cloudinary**: Specialized image storage, CDN, optimization
✅ **Local Storage**: Fast access, offline capability, no billing required

// Firebase Authentication

  uid: "Xm9Kp2RtL4...",

  "agrof_users": {

      username: "Saga",
      phone: "+256705223777",

### **After Photo Upload:**
```javascript
// Cloudinary

{
  "agrof_users": {
    "Xm9Kp2RtL4...": {
      ...
      profilePhoto: "https://res.cloudinary.com/.../profile.jpg",  // ✅ Cloudinary URL
      updatedAt: "2025-10-10T12:34:56.789Z"
    }
  }
}
```

## ❌ **The "No current user" Error**

This error means:
```javascript
currentUser = null  // No user signed in!
```

**Solution**: User must sign in first before editing profile.

### **Flow:**
```
1. User opens app
   ↓
2. If not signed in → Go to Account tab → Sign up/Login
   ↓
3. Firebase Auth signs in → provides UID
   ↓
4. App loads user data → currentUser = {...}
   ↓
5. Now user can edit profile ✅
```

---

## 🚀 **Summary**

Your AGROF app uses a **hybrid storage architecture**:

- 🔐 **Firebase Authentication** - User identity & security
- ☁️ **Cloudinary** - Profile photos only
- 💾 **Local Storage** - User profile data & offline access

**Firebase UID** connects everything together!

**To fix the error:** Make sure the user is signed in (check Account tab authentication status) before trying to save profile changes.
